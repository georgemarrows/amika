Useful prototype details

implementation hints
  • The queue intentionally interleaves recognition and production cards, but each card keeps its own due date, interval, ease, reps, and lapses.
  • The same kanji can look mature for recognition and fragile for production, so the kanji page should show both states instead of one combined SRS badge.
  • Rating buttons show the next interval preview from the current card state. The exact scheduler math can change without changing this UI shape.
  • Removing a kanji from SRS should probably disable both card kinds while preserving review history for re-enable and future import/debugging.
